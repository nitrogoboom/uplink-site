# src/ – the site in parts

**Branch `astro` (28 Oct 2026):** this folder is becoming an Astro project. Astro reads `pages/*.astro`, `layouts/`, `components/`, `styles/`, `scripts/`. Every page is converted (`pages/*.astro`, `components/<page>/`), and the content is data: `content/services/*.json`, `content/projects/*.json` (one page each: `pages/services/[slug].astro`, `pages/work/[slug].astro`), `data/*.json` for the smaller lists, typed in `content.config.ts`. The old parts described below live in `legacy/` for reference only; nothing reads them. The old build commands below do not run on this branch.

---

Edit pages here, not in `site/`. Then run:

```
python tools/build_pages.py
```

That joins the parts into `site/*.html` and `site/assets/css/site.css`, and adds the `?v=` stamps. `python tools/build_pages.py --check` says if `site/` is out of date.

Every file starts with a note saying what it is (`<!--- ... --->` in HTML, `/*--- ... ---*/` in CSS). The build drops the notes.

## Pages: one folder each

Files are numbered in the order they appear on the page. The HTML, CSS and drawing for one section share a number.

| Folder | Builds | Sections |
|---|---|---|
| `pages/home/` | `index.html` | 1 hero (+ office drawing) · 2 services · 3 grow (+ tower drawing) · 4 process · 5 proof |
| `pages/services/` | `services.html` | 1 pick a service · 2 plans · 3 FAQ |
| `pages/work/` | `work.html` | 1 projects · 2 details · 3 project pop-up · 4 industries |
| `pages/about/` | `about.html` | 1 profile · 2 story · 3 team |
| `pages/contact/` | `contact.html` | 1 message · 2 support |
| `pages/soon/` | `soon.html` | 1 intro |
| `pages/404/` | `404.html` | 1 intro |

`page.html` in each folder is the page's `<head>` plus the list of parts in order. A line like `<!-- @include 2-services.html -->` pulls in that file. To move a section, move its line. To add one, make the file and add a line.

A section with no `.css` of its own uses shared styles; its note says which.

## Drawings in the home page

`1-hero-office.svg` and `3-grow-tower.svg` are written by `tools/gen_office.py` and `tools/gen_tower.py`. Don't edit them by hand. Those scripts rebuild the pages when they finish.

## Shared parts: `components/`

On every page. `<!-- @include Header -->` pulls in `components/Header.html`.

- `Header.html` – logo, page tabs, support and portal buttons
- `BottomNav.html` – the tab bar on phones
- `Footer.html` – generated by `tools/build_footer.py`; edit the lists there
- `BookDialog.html` – "Book your free check-up" pop-up
- `ShortcutsDialog.html` – keyboard shortcuts pop-up

The build fills in the bits that change per page: the current tab and root links (`/services`) on the 404 page.

## CSS: `styles/`

`styles/site.css` is the list of CSS files in cascade order. Later files win a tie, so order matters. Shared styles live in `styles/`; a section's own styles sit next to it in its page folder. Each page gets the shared styles plus only its own folder's CSS, so a class used on two pages belongs in `styles/` (or in `BORROWS` in `tools/build_pages.py` until it moves). After moving CSS around, run `python tools/verify_css_split.py` with the server up.

`styles/desktop.css` holds the desktop layout (≥ 1100 wide, ≥ 700 tall) for every page in one block. Its comments mark which section each part is for.

Colours, sizes and timings stay in `site/assets/css/tokens.css`. Scripts stay in `site/assets/js/`.

## Moving to Astro

The layout matches Astro on purpose. The full plan (target layout, config choices, order of work) is `review.md` at the root. In short:

- `components/Header.html` → `src/components/Header.astro`, and so on
- each numbered section → a component, e.g. `src/components/home/Hero.astro`, with its `.css` as the component's `<style>`
- `page.html` → `src/pages/index.astro`: the `<head>` goes into a shared layout and each `@include` line becomes `<Hero />`
- the per-page bit the build fills in (current tab) becomes a prop
- services, projects, FAQ, plans, team and footer links become content collections, and each service and project gets its own page
