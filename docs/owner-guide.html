The site

  • Live: uplink-site.johnoreilly.workers.dev (hidden from search engines until launch).
  • Code and docs: github.com/nitrogoboom/uplink-site.
  • Previews: each pull request gets its own preview link, posted as a comment on it. Previews never touch the live site.
  • Stage: draft. Almost every word is placeholder and about to be rewritten.

How work gets done

  1. You ask a Claude session for a change, in plain words.
  2. The agent does everything else: edits, builds, runs the right checks, and opens a pull request. You don't run commands.
  3. Visual changes wait for you. The agent sends the preview link; you look, then say merge.
  4. Everything else merges by itself once its checks pass.
  5. Each merge goes live in about 2 minutes. The deploy tests the new version first and rolls back by itself if it's broken.
  6. Docs changes are saved to GitHub but never go to the live site.

Checks scale with the change: a wording change takes seconds, layout a minute, scripts and setup run the full set. The full release checks run only before launch.

  • Give each secret an owner and a date to replace it.
  • An outside uptime check on the live address.
  • The repository is public for now; making it private turns off its protection rules unless the plan is GitHub Pro.

The site's words

Every word on the site lives in plain text files, so a rewrite never touches code. A missing or misspelled entry stops the build, so nothing breaks silently.
