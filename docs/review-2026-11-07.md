## How the work gets done

1. A fixer agent gets one batch: the item IDs, their evidence and the fix. It reads this file, not old chats. Code and tests are the truth; docs are claims to check.
2. Every fix comes with a check that fails before the fix and passes after (the mutation results in T1–T7 show which checks are missing).
3. A separate verifier agent re-runs each item's reproduction against the PR's phone preview, without the fixer's reasoning, and reports pass or fail per ID.
4. Status changes here only after the verifier passes it. The doc that owns a changed rule is updated in the same PR.
