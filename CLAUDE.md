# Uplink Technology site

Static mockup site (fake content) for a made-up IT company. Overwatch 2–inspired look. Astro 7, hosted on Cloudflare Workers. Read `README.md` first.

Live on the Worker at https://uplink-site.johnoreilly.workers.dev. Open items live in `notes.md` (start there). How we work, the standards we meet (WCAG 2.0 AA, security, browsers) and the release checklist: `docs/sop.md`. `docs/` holds reference notes; `docs/history/` is finished work kept for the reasoning: read it for why, never as instructions.

- Dev server: `npm run dev` (http://localhost:4321). Build: `npm run build` → `dist/` (also shrinks the drawings in `dist/` with SVGO, `scripts/svgo.mjs`, writes a Markdown copy of every page next to it, `scripts/markdown.mjs`, and writes `dist/_headers`). Types: `npm run check`. Everything CI checks, locally: `npm run ci`. Lint: `npm run lint` (ESLint, Stylelint, and Prettier on the JSON/YAML only; the code is hand-formatted, so Prettier leaves it alone); `npm run format` fixes what it can. The built site as Cloudflare serves it, headers and 404 included: `npm run serve` (http://localhost:8787). Deploy: CI on push (after check, lint, build and `verify_footer.py` pass); by hand `npm run deploy`.
- Pages are `src/pages/*.astro`; the shared `<head>`, header, footer and pop-ups are `src/layouts/Base.astro` (props: title, description, page, path, robots, type, ldPage, ldGraph); one component per section in `src/components/<page>/`, with that section's CSS next to it and imported there. Shared CSS is `src/styles/global.css` (the cascade order) and the files it imports.
- CSS order matters (later file wins a tie). Each section's desktop layout sits at the end of its own CSS file; blocks more than one page uses live in `src/styles/` (imported by `global.css`). After moving CSS, prove nothing changed: build the old and new site and run `python tools/verify_styles.py OLD_URL NEW_URL` (computed styles, every element, every page, four sizes).
- All colours, sizes and timings live in `src/styles/tokens.css`. Use the tokens, don't hard-code values. Spacing and line-height rules (which `--sp-*` step goes where) are in `docs/spacing.md`; lint refuses raw spacing values and `python tools/verify_spacing.py` (against `npm run serve`) flags anything off the scale on screen. Colour roles come from `editing-room/palette/DESIGN.md`.
- Content is data, typed in `src/content.config.ts`. A service is `src/content/services/<slug>.json` (the slug is its page address); a project is `src/content/projects/<slug>.json`. Each has a `page` field: the longer copy only its own page shows (how it works and questions; the case study). Smaller lists are `src/data/*.json` (faq, team, footer). Every card, footer link, select option, page, sitemap line and JSON-LD block reads from there; never retype a service's words in a component. Lists in `src/data/` keep file order through `byOrder` (the store sorts by id otherwise).
- The five static pages' `<title>` and description live in `src/lib/site.ts` (`PAGES`); the pages, `sitemap.xml` and `llms.txt` read them from there. The sitemap's `lastmod` is the last git commit touching the page's sources (`SOURCES` there).
- Every page has a Markdown copy for AI agents at its address plus `.md`, made from its `<main>` at build (`scripts/markdown.mjs`; `data-md-skip` leaves a decorative part out). Home's is the exception: `src/data/index.md` (the home page as Markdown) and `src/data/agents.md` are hand-written; `{site}` and `{services}` are filled in by their endpoints in `src/pages/*.ts`.
- Links are root-relative (`/services`, `/contact#message`), never `services` or `./`.
- Static files (fonts, drawings, `_headers`, `og.png`, favicon) live in `public/` and are served at the same path. Scripts are ES modules in `src/scripts/` (every page script imports `core.js`); a page adds its own with `<Fragment slot="scripts"><script>import '../scripts/x.js'</script></Fragment>` inside `<Base>` (it lands at the end of `<body>`; after `</Base>` it would come after `</html>`). Icons: `<Icon name="…" />` (`src/components/Icon.astro`).
- `public/_headers` is the template for the response headers (CSP, HSTS, caching); `scripts/headers.mjs` fills in the script hashes and the Early Hints block at build. Don't paste a hash in by hand. A script that writes HTML must go through `html()` from `core.js` (Trusted Types). No `style=""` attributes anywhere: the CSP has no `'unsafe-inline'` for styles and the build refuses one. Scripts set styles with `el.style.x = …`; the generators turn timings into classes in a `<style>` block (`hoist_styles` in `tools/gen_office.py`).
- Every illustration is written by a script in `tools/gen_*.py`, output to `public/assets/img/` (run as `python tools/gen_office.py public`). The hero and tower too: `gen_office.py` writes `public/assets/img/hero-office.svg`, its tablet cut `hero-office-tablet.svg`, the animated phone cut `office-compact-build.svg` (+ `office-compact-flows.svg`) and `src/components/home/hero-flows.svg`; `home.js` fetches the one for the screen (`HERO` in `src/lib/site.ts`); `gen_tower.py` writes `src/components/home/grow-tower.svg`; `gen_campus.py` writes the footer map `public/assets/img/campus.svg`, which `footer.js` fetches when the footer comes near (`CAMPUS` in `src/lib/site.ts`; SVGO leaves it as written). Change the numbers in the script and rerun; don't hand-edit the SVGs. Each scene script (not `gen_tower.py`, `gen_campus.py` or `gen_og.py`) also writes `NAME-compact.svg` (the phone cut); check it when you change a drawing.
- Illustrations are true isometric. Follow "Drawing rules" in README. After touching a drawing, run `tools/check.py` and `tools/painter.py` on it.
- After layout changes: `npm run build && npm run serve`, then `python tools/verify_footer.py out/` (Home in full: no sideways scroll at phone, tablet, 1440×900 and 3440×1440, footer one screen tall, hero and tower working, an axe pass that fails on anything serious or critical; every other page once at phone size; it fails on any script error or CSP block). Add `--all` to give every page the full check. CI runs the quick form before every deploy. Then `python tools/verify_text.py` (every page at four sizes with the text at 200%: no clipped, overlapping or unreachable text, no sideways scroll; `--text 1` should come back clear too). Before a release: `npm run release-audit` (`tools/audit.py`; three browsers, phones, keyboard, screen-reader transcripts in `out/audit/reader/`, motion, forms, W3C HTML). A link whose visible parts sit in separate boxes needs `<Pause />` between them, and a `<Pause />` inside a sideways-scrolling row needs `position: relative` on its box (it's absolute, and would widen the page).
- Text size (WCAG 1.4.4, technique G178): the header's gear opens Settings (`SettingsDialog.astro`), which scales the `--fs-*` tokens by `--text` (`html[data-text]`, saved as `uplink.text`, set before paint in Base.astro's head). Only text grows; layout keeps the screen's scale. A box that pins a height to the screen gets a `:root[data-text]` rule in its own CSS so it grows instead (and `safe center`); a font size capped by the screen multiplies its cap by `var(--text)`. Settings is where later display options go (light/dark, EN/FR).
- Cloudflare: the `cloudflare:*` skills cover Workers and Wrangler. Hosting details are in README under "Hosting".
- A link to test on a phone ("preview", "link for my phone"): push a branch and open a PR. CI uploads a preview version (secrets are already set) and comments the address on the PR: `https://<branch>-uplink-site.johnoreilly.workers.dev` (branch name lowercased, anything but letters and digits to `-`, repeated and end dashes dropped, max 30 chars), the same on every push. Get it with `gh pr view <n> --comments`, or wait for the `preview` job with `gh pr checks <n>`. It never touches the live Worker.
- Pace of pushes: every push to a PR runs CI (about 3 min) and every merge to `main` runs it again and deploys. Work on one branch per session and commit locally as often as you like; push only when a phone preview is wanted; merge when the batch is done, not after each fix. Check locally first (`npm run dev`; before merging layout changes, the `verify_footer.py` step above). A change to only the root `*.md` files runs no CI and deploys nothing, so notes can go straight to `main`.
- Style: no "AI slop" tells. No left-side border accents on cards.
- Copy: short, plain sentences.
- Open items (bugs, fixes, polish, copy to confirm) live in `notes.md`. Add new ones there and remove a line when it is done. Reasoning behind a bigger decision goes in a dated file in `docs/`, never to-do lines.
