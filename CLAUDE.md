# Uplink Technology site

Static mockup site (fake content) for a made-up IT company. Overwatch 2–inspired look. Astro 7, hosted on Cloudflare Workers. Read `README.md` first.

**State (28 Oct 2026):** the move from the old Python build to Astro is merged to `main` (plan and reasoning in `review.md`) and live on the Worker at https://uplink-site.johnoreilly.workers.dev; the old Pages site is deleted. Open items live in `notes.md` (start there); `next.md` (lint, a11y, CSP styles, CSS housekeeping, script imports, page layouts, images) is done.

- Dev server: `npm run dev` (http://localhost:4321). Build: `npm run build` → `dist/` (also shrinks the drawings in `dist/` with SVGO, `scripts/svgo.mjs`, writes a Markdown copy of every page next to it, `scripts/markdown.mjs`, and writes `dist/_headers`). Types: `npm run check`. Lint: `npm run lint` (ESLint, Stylelint, and Prettier on the JSON/YAML only; the code is hand-formatted, so Prettier leaves it alone); `npm run format` fixes what it can. The built site as Cloudflare serves it, headers and 404 included: `npm run serve` (http://localhost:8787). Deploy: CI on push; by hand `npm run deploy`.
- Pages are `src/pages/*.astro`; the shared `<head>`, header, footer and pop-ups are `src/layouts/Base.astro` (props: title, description, page, path, robots, type, ldPage, ldGraph); one component per section in `src/components/<page>/`, with that section's CSS next to it and imported there. Shared CSS is `src/styles/global.css` (the cascade order) and the files it imports.
- CSS order matters (later file wins a tie). Each section's desktop layout sits at the end of its own CSS file; blocks more than one page uses live in `src/styles/` (imported by `global.css`). After moving CSS, prove nothing changed: build the old and new site and run `python tools/verify_styles.py OLD_URL NEW_URL` (computed styles, every element, every page, four sizes).
- All colours, sizes and timings live in `src/styles/tokens.css`. Use the tokens, don't hard-code values. Spacing and line-height rules (which `--sp-*` step goes where) are in `spacing.md`; lint refuses raw spacing values and `python tools/verify_spacing.py` (against `npm run serve`) flags anything off the scale on screen. Colour roles come from `editing-room/palette/DESIGN.md`.
- Content is data, typed in `src/content.config.ts`. A service is `src/content/services/<slug>.json` (the slug is its page address); a project is `src/content/projects/<slug>.json`. Each has a `page` field: the longer copy only its own page shows (how it works and questions; the case study). Smaller lists are `src/data/*.json` (faq, team, footer). Every card, footer link, select option, page, sitemap line and JSON-LD block reads from there; never retype a service's words in a component. Lists in `src/data/` keep file order through `byOrder` (the store sorts by id otherwise).
- The five static pages' `<title>` and description live in `src/lib/site.ts` (`PAGES`); the pages, `sitemap.xml` and `llms.txt` read them from there. The sitemap's `lastmod` is the last git commit touching the page's sources (`SOURCES` there).
- Every page has a Markdown copy for AI agents at its address plus `.md`, made from its `<main>` at build (`scripts/markdown.mjs`; `data-md-skip` leaves a decorative part out). Home's is the exception: `src/data/index.md` (the home page as Markdown) and `src/data/agents.md` are hand-written; `{site}` and `{services}` are filled in by their endpoints in `src/pages/*.ts`.
- Links are root-relative (`/services`, `/contact#message`), never `services` or `./`.
- Static files (fonts, drawings, `_headers`, `og.png`, favicon) live in `public/` and are served at the same path. Scripts are ES modules in `src/scripts/` (every page script imports `core.js`); a page adds its own with `<script>import '../scripts/x.js'</script>`. Icons: `<Icon name="…" />` (`src/components/Icon.astro`).
- `public/_headers` is the template for the response headers (CSP, HSTS, caching); `scripts/headers.mjs` fills in the script hashes and the Early Hints block at build. Don't paste a hash in by hand. A script that writes HTML must go through `html()` from `core.js` (Trusted Types). No `style=""` attributes anywhere: the CSP has no `'unsafe-inline'` for styles and the build refuses one. Scripts set styles with `el.style.x = …`; the generators turn timings into classes in a `<style>` block (`hoist_styles` in `tools/gen_office.py`).
- Every illustration is written by a script in `tools/gen_*.py`, output to `public/assets/img/` (run as `python tools/gen_office.py public`). The hero and tower too: `gen_office.py` writes `public/assets/img/hero-office.svg`, its tablet cut `hero-office-tablet.svg`, the animated phone cut `office-compact-build.svg` (+ `office-compact-flows.svg`) and `src/components/home/hero-flows.svg`; `home.js` fetches the one for the screen (`HERO` in `src/lib/site.ts`); `gen_tower.py` writes `src/components/home/grow-tower.svg`. Change the numbers in the script and rerun; don't hand-edit the SVGs. Each script also writes `NAME-compact.svg` (the phone cut); check it when you change a drawing.
- Illustrations are true isometric. Follow "Drawing rules" in README. After touching a drawing, run `tools/check.py` and `tools/painter.py` on it.
- After layout changes: `npm run build && npm run serve`, then `python tools/verify_footer.py out/` (no sideways scroll at phone, tablet, 1440×900 and 3440×1440, footer one screen tall, hero and tower working, and an axe pass on every page that fails on anything serious or critical).
- Cloudflare: the `cloudflare:*` skills cover Workers and Wrangler. Hosting details are in README under "Hosting".
- A link to test on a phone ("preview", "link for my phone"): push a branch and open a PR. CI uploads a preview version (secrets are already set) and comments the address on the PR: `https://<branch>-uplink-site.johnoreilly.workers.dev` (branch name lowercased, non-letters to `-`, max 30 chars), the same on every push. Get it with `gh pr view <n> --comments`, or wait for the `preview` job with `gh pr checks <n>`. It never touches the live Worker.
- Style: no "AI slop" tells. No left-side border accents on cards.
- Copy: short, plain sentences.
- Open items (bugs, fixes, polish, copy to confirm) live in `notes.md`. Add new ones there and remove a line when it is done. `review.md` holds the reasoning behind the bigger ones and `next.md` the order to do them in; don't add to-do lines to `review.md`.
